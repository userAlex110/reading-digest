# 卡片式阅读：设计说明

这一阶段只比较读法，不替换线上页。`data/articles.json` 和 `scripts/build.js` 保持不动，根目录 `index.html` 也不动。三套可以点开的原型在 `prototypes/`，都由真实的 21 篇生成。

看过的材料是各产品的公开文档、帮助页和评述，不是登录后的个人库。下面只写这些来源里确实能核对的行为。

## 要解决的事

现在的页面把一批文章收成色块分区。分区本身还能找，但每一篇不够像「一篇」：标题、摘要、讲解和原文挤在同一条长卷里，手机上要靠滚动碰运气，桌面上分类一多，颜色就代替了结构。

主人要的是另一件事：每一篇都是一张小卡片。

- 手机一次只读一张，能翻、能滑，知道自己在第几张，并且能回到目录。
- 桌面是整齐的卡片墙，可以按分类或按时间重排，筛选要一眼能看见。
- 抓取失败的两篇必须一眼就能和其余分开。

## 参照

### Readwise

[复习高亮的两种模式](https://docs.readwise.io/readwise/docs/faqs/reviewing-highlights)。Review Mode 一次一张，Scroll Mode 把同一批摊在一页上；列表和网格是同一批内容的两种图标，不是两个产品。位置靠左右箭头，键盘也很完整。

可取的是「一张 / 一列」可以切换，以及随时知道自己在第几条。不可取的是它在做间隔重复，不是在做档案：箭头会跳过而不是阅读，Keep / Discard 会把没读完的东西清掉。社区里也有人指出只靠滑动和按钮，状态会对不上。Daily Review 还会插入无关卡片。这些都不该进一个个人学习站。

配色方面，[偏暖的编辑风评述](https://pageproofer.com/inspiration/warm-editorial/readwise/)里奶油纸、墨色和橙色之外还有高亮黄。颜色已经超过两色，黄条是高亮产品的记号，不是阅读档案该有的记号。

### Matter

[The Sweet Setup 的队列描述](https://thesweetsetup.com/apps-were-trying-matter/)和 [Robert Breen 的阅读笔记](https://robertbreen.com/2025/02/27/elevate-your-online-reading-with-matter/)。队列是密列表：标题、阅读时间、进度、批注数。右滑优先、左滑归档，排序和筛选是一等控件。真正的阅读器把衬线排开，界面在读的时候让开。

可取的是安静的阅读面，以及「怎么排」本身就是按钮，不是藏在设置里的偏好。不可取的是队列并不是卡片，摘要要靠向下的手势才出现；摇一摇打乱顺序曾经是彩蛋，后来收进菜单，说明它好玩但不适合当档案的默认动作。一篇要先被看见摘要，再决定要不要展开讲解。

### Are.na

[频道与 block](https://help.are.na/docs/getting-started/channels)、[对待 block 的说明](https://help.are.na/docs/guides/handling-blocks-with-care)，以及 [新网页端 Sander 的介绍](https://www.are.na/editorial/introducing-sander-our-new-web-client)。一个频道是一堆 block。网格里图片、文字、子频道混在一起，界面本身几乎只有黑白灰，颜色来自内容。手机上点开是盖在网格上的一层，可以横向滑过相邻 block，向下滑回到网格。

可取的是：网格和单张是同一批对象，退出单张就是回到刚才的网格，而不是另开一个阅读器产品。不可取的是它为图片服务。纯文字 block 在格子里显得空，没有阅读进度，顺序靠手拖，不靠时间或标签。我们的 21 篇没有图，瀑布流会把该连着读的次序打散。

### Raindrop

[收藏夹](https://help.raindrop.io/collections)、[标签](https://help.raindrop.io/tags)、[筛选](https://help.raindrop.io/filters)，以及视图字段里的 list / simple / grid / masonry。同一个收藏可以在列表、方格、标题、拼贴之间换，换的是视图不是另一套数据。一篇书签只属于一个收藏，跨组靠标签。没有命中的筛选项不出现。

可取的是视图开关，还有「只为存在的类目提供筛选」。不可取的是方格会裁掉标题，拼贴是给图片的；收藏本身的图标和颜色很容易变成第二套彩虹。一篇文章不该为了出现在两个分类里被复制一份。这里分类是文章自己的字段，筛选切的是同一批卡片。

### Pocket

[Mozilla 关闭 Pocket](https://techcrunch.com/2025/05/22/mozilla-is-shutting-down-read-it-later-app-pocket/)（2025-07-08 停止，之后数据删除）。[Raindrop 的对照](https://blog.raindrop.io/pocket-alternatives/)写得很直：Pocket 是一条长列表，Raindrop 才提供卡片、标题、板和列表。[MacStories 对同类稍后读的描述](https://www.macstories.net/reviews/folio-a-promising-read-later-app-with-a-strong-foundation/)也是标题、来源、阅读时间、缩略图、标签。

可取的只有一件：卡片上要看来源，以及你为什么留下它（在这里就是摘要）。不可取的是缩略图压过正文，而且没有「一次读一篇摘要」这层。产品已经停掉，不值得再模仿它的列表。

### Glasp

[网页高亮](https://glasp.co/web-highlighter)和 [界面记录](https://screenrove.com/glasp/design)。库是三栏：人、一列页面卡片、右侧细节。一张卡片往往是一段被标过的文字，左边一条彩色边。高亮色有粉、黄、绿、蓝四支，再加上链接蓝。

可取的是：卡片的正文就是那段值得留下的话，不是一张空标题。不可取的是高亮色本身就是产品，四种记号色已经破了「大约两种主色」。它也没有「摘要 + 可展开的讲解」这种结构，社交栏和这篇学习站无关。[嵌入块](https://glasp.co/posts/how-to-embed-glasp-highlights-on-note-taking-apps-and-websites)还不能按自己的版式改。

### Omnivore

[仓库说明](https://github.com/omnivore-app/omnivore)和 [The Verge 的停服报道](https://www.theverge.com/2024/10/29/24283055/one-of-my-favorite-read-later-apps-is-shutting-down)。标签、高亮、整套键盘、可读性解析都在。库的脸是邮件式列表，不是卡片。云服务已在 2024 年 11 月停掉，只剩自托管。

可取的是标签真的能筛，键盘能翻。不可取的是收件箱密度：21 篇如果排成邮件，摘要和讲解又会掉回现在这条长卷。服务停掉也说明，不该把「导入导出工作流」当成版式。

### 即刻

[优设记录的吸附](https://www.uisdc.com/hunter/0221602164.html)：信息流把每张高度不一的卡片顶边吸到栏下，避免停在一张的腰上。[人人都是产品经理对话题标签的拆解](https://www.woshipm.com/pd/1939474.html)：标签在卡片上，点标签进话题，点正文进这条帖；把好几条合成一张「聚合卡」会浪费曝光，因为多数人根本不会滚到被裁掉的下半张。

可取的是一张帖就是一张卡，标签是入口不是色点，以及一张卡要从头开始、不要停在半截。不可取的是无限社交流、头像和情绪化的界面。这里没有「最新回复」可刷，时间分组必须稳定，不能被新帖挤乱。

### 小红书

[个人页双列瀑布](https://feedpeek.app/zh/guides/rednote-profile-grid)按图片真实比例排，新的在左上，短列优先，所以新卡片一来，原有位置会重排，底部参差是故意的。[公开的界面笔记](https://github.com/nexu-io/open-design/blob/main/design-systems/xiaohongshu/DESIGN.md)里卡片是白底、圆角、默认无阴影：图、一两行标题、头像和赞。电脑上大约五列。点进去是图片轮播和评论，不是一篇文。

可取的是分工：格子负责挑选，一次看完负责阅读。不可取的几乎是卡片的其余部分。这些文章没有图，瀑布会打乱时间顺序，标题被收成脚注。分组也不能在「按标签」和「按时间」之间切换。

### Notion 与画廊

[画廊视图](https://www.notion.com/help/guides/gallery-view-databases)可以调卡片大小、封面、筛选，说明里也写画廊能分组。[视图、筛选与排序](https://www.notion.com/help/views-filters-and-sorts)把分组放在视图设置里，空组可以藏掉。[看板](https://www.notion.com/help/boards)则是按一个属性分成几列。[API 对视图的说明](https://developers.notion.com/guides/data-apis/working-with-views)更严格：`group_by` 属于表格和看板，画廊是封面加属性，并不是分组视图。[分组指南](https://www.notion.vip/insights/the-grouping-guide)把组写成同一视图下按属性值切开的子视图，日期可以按日、月、年。

可取的是同一批卡片换一个分组维度就重新归堆，空组不占位，卡片脸上要有标签、日期、来源这些属性。不可取的是卡片只是数据库的一行，没有首字下沉，也没有阅读进度；分组标题像软件字段名。画廊还偏向封面图。我们要的分组是杂志的「章」，不是看板。

## 从这些参照里留下的

1. 手机上的一张和桌面上的一格是同一篇，不是两个版式各写各的。
2. 「按时间 / 按分类」是开关。筛选只列出这 21 篇里真正有的类。
3. 摘要印在卡片上。讲解默认收着，打开才占地方。
4. 要有第几张，还要有一份可以点的目录回到任意一篇。
5. 主色停在墨色和朱砂。纸色是底，不是第三种颜色。分类写成字，不再用原来的八种颜色。
6. 抓取失败是另一种物件状态：虚线、斜印「未录入」、标题用意大利体、没有首字下沉、链接写成「尝试打开原文」。不给它第九种颜色。
7. 不用瀑布流。这些卡片是文字，顺序要能对上日期和分类。

## 气质

暖纸色 `#f4efe4`，墨色 `#2c241c`，朱砂 `#8f3d32`。字体是衬线（屏幕上用 Noto Serif CJK SC，主人的系统上会落到宋体）。阅读进度是一条 3 像素的细轨：手机上表示这叠走到第几张，桌面上表示整页滚了多少；方案 C 的阅读层则表示这一篇自己滚了多少。首字下沉只用在真正在读的正文上——手机整张，以及展开后的摘要——桌面小格如果又要截断行数又要下沉，首字会被切掉，所以小格不下沉。

三套用同一套颜色和同一批字段。差别在结构，不在皮肤。

## 三套

重新生成（只会写 `prototypes/`）：

```bash
node prototypes/render.js
```

直接打开 `prototypes/a.html`、`b.html`、`c.html` 即可，数据已经嵌在页面里。窄于 800 像素是手机，宽于它是桌面。手机上的筛选和排列收在「目录」里，卡片本身保持干净。方向键可以翻页，Esc 关掉目录或阅读层。

失败的两篇是 DeepSeek Harness 团队的文字分享，和 TRAE 官方训练营。按时间从新到旧、同一天再按分类顺序排，TRAE 是第 6 张。

### A · 册页

手机是横向翻页。一屏一张，长摘要在卡片内部上下滚，不会和左右翻页抢手势。底部是上一张、第几张、下一张；第几张可以打开目录。桌面按日期或分类分成章，章名用大字，下面三列小卡，朱砂左边线只出现在已录入的卡片上。讲解在格子里展开。

像一本按日子分册的杂志。翻页最稳，因为左右和上下分工明确。

### B · 目录卡

手机改成纵向吸附。每张比一屏略短，下一张的顶边露出来，右侧一排刻度表示位置。上一张和下一张放在顶栏，避免只能靠滑。桌面左边是索引，跟着「按时间 / 按分类」变成日期或类目；右边是双线书目卡，格子比 A 宽，摘要多留两行。首字下沉要等讲解打开才出现。

适合顺着目录找，不像在读。21 篇还好，篇目再多时，这侧栏会比 A 的章标题更有用。

### C · 牌叠

手机是物理的一叠。下一张从右下露出一角，按住卡片向左拂过大约 80 像素就换下一张，向右回到上一张；底下仍有按钮。进度写成「第几张 / 还剩几张」。目录是编号清单。桌面变成四列编号小卡，摘要仍在，但只有两三行。点「展开讲解」才进入一篇衬线阅读页，进度改记这一篇的滚动。

和 A、B 的差别最大：桌面先是索引，阅读是盖上来的一页。拂动手势容易被当成滚动，所以不能只留手势。

## 建议

采用 **A · 册页** 作为下一轮替换线上页的方向。

原生的横向吸附最不容易和正文滚动打架，摘要一直在卡片上，桌面的分章也符合「按时间或按分类排好」这句话。B 更像目录学，扫描快，但读起来像在查卡片箱；侧栏可以等篇目明显变多再借过来。C 的阅读层好看，但小卡把讲解藏到另一次点击之后，拂动又容易错过。不要把 C 的拖拽当成手机上的唯一路径。

失败态、两色、进度和首字下沉三套已经共用，换结构时不必再换一套皮肤。
