150 元的「智能锁贴」：不换锁芯，夹在旧锁上就能远程开门

立创开源硬件平台

一句话

立创开源项目 LockDrive 用 ESP32-C3 + 减速电机 + 同步带 + 可换夹具，夹在原有门锁旋钮上带动开锁；支持 4 种锁型、蓝牙与远程开锁、撬锁警报和开锁日志，作者给出的复刻成本约 150 元。

深入讲解 · 为什么「贴」比「换」聪明，闭环与功耗怎么算

  1. 背景：作者搬过几次家，没有一位房东同意拆锁换智能锁，于是做了这个「智能锁贴」
  2. 七项功能：手机 App 远程开锁、蓝牙开锁、4 个圆形夹具适配 4 种锁、不影响继续用钥匙开锁、撬锁警报、加密存储 50+ 条开锁日志、续航约 6 个月
  3. 报警逻辑：MPU-6050 监测异常震动 → 锁死电机 + 推送警报 + 超过 2 次确认后蜂鸣器报警
  4. 硬件清单：主控 ESP32-C3、电池管理 TP4056、DC-DC SGM6036-3.3、陀螺仪 MPU-6050、电机驱动 TC118S、蜂鸣器 HYG-9605B、磁编码器 AS5600、两节 18650 供电
  5. 机械结构：ESP32-C3 控制 TC118S 驱动 520 减速电机 → 同步带 → 中空大齿轮 → 可更换夹具 → 带动原锁旋钮完成开关锁
  6. 闭环与软件：AS5600 实时反馈旋转角度，实现精准开关锁；软件基于 ESP-IDF v5.5 + FreeRTOS，手机 App 与 ESP32-C3 通信
  7. 开源与成本：源码、外壳、电路均已开源，作者给出的参考复刻成本约 150 元；项目页：oshwhub.com/foiuuy/project_cvzewjvd
  8. 注意：原文是立创开源硬件平台的项目介绍，文末带星火计划与商城活动推广；功能描述以作者自述为准

一、不改锁芯，绕开的是「房东 + 门体」两道约束

租房场景里，换智能锁要拆原锁、改门孔，退租还得复原；这个项目把执行机构做成一个外挂贴：夹具夹住原旋钮，电机带着旋钮转，原锁芯和钥匙完全不动。好处是可逆、无损、搬家能带走；代价是对夹具的适配和安装同心度要求高——夹具打滑，再好的电机也开不了门。

二、为什么要加磁编码器做闭环

开环控制只知道「电机转了多少步」，不知道「锁舌到底转到位没有」。夹具公差、皮带打滑、电池电压下降都会让实际角度偏离。AS5600 把旋钮角度实时反馈给 ESP32-C3，控制器才能判断「到位/没到位/被卡住」，这也是它能做精准开关锁和异常检测的基础。原文没有披露具体的控制算法与阈值，不能假设它已经做到工业级可靠。

三、安全与功耗，原文说到的和没说的

说到的：异常震动锁死电机、推送、二次确认后蜂鸣器报警、开锁日志加密存储 50+ 条。没说的：加密方式、通信协议、云端权限模型、断网/没电时的降级策略。两节 18650 撑 6 个月，意味着大部分时间必须深度休眠，只在蓝牙连接或定时唤醒时工作——电机峰值电流很大，电源设计（TP4056 + SGM6036）和休眠策略才是续航的关键。
📌 复刻提醒：这是门锁，不是玩具。先确认租房合同与消防/安全要求；保留钥匙开锁的备份路径；不要把开锁权限交给来路不明的云端服务。原文只给到参考成本，实际还要算夹具加工、PCB 打样和电池的费用。

四、和你做过的项目是同一类

它和站内那台 ESP32 滚纸写字机共享同一套骨架：ESP32 + 电机驱动 + 机械传动 + 现成固件/框架。区别在于这个项目多了传感器闭环和安全逻辑，更适合作为「有真实痛点、能演示、成本可控」的作品放进履历。

杭电前几任 ACM 队长去哪了？外加蓝桥杯、实习与「考研还是工作」五问

夜深人静写算法

一句话

一篇社群问答合集：作者列了杭电前六任 ACM 集训队队长的去向（网易、游戏公司、字节等），并回答了蓝桥杯路线、大二要不要实习、C 语言大数组放哪、考研还是找工作等问题；作者的核心建议是把实习放在大三、用海投和面试查漏补缺。

深入讲解 · 队长样本、竞赛路线与实习时间账

  1. 队长去向（作者自述）：第一届卢**** 网易雷火事业群技术副总裁；第二届徐**** 网易《倩女幽魂》主程；第三届林** 网易某爆款项目主程；第四届黄**** 游戏公司合伙人（CTO）；第五届作者本人，全网 300 万粉丝技术博主；第六届胡** 四块 ACM 亚洲赛金牌、两届 WorldFinal、字节某线负责人
  2. 作者对「队长」的判断：校队能不能重启和队长没关系，需要的是教练；队长的作用是榜样，以激情感化团队
  3. 蓝桥杯语言选择：平时练习可以用 C，比赛用 C++ 更好——STL 省去手写数据结构；但会调 STL 不等于不用学数据结构原理
  4. 训练路径：C++ 面向过程 → 面向对象 → 基础数据结构 → STL → 基础算法 → 进阶数据结构 → 进阶算法；看视频要跟着写代码并加入自己的思考
  5. 大二实习：作者不建议；大二课最多，实习多是感受工作氛围，像「计算机网络处」这类岗位能力提升不大
  6. 考研还是找工作：先准备简历 → 海投实习 → 面挂了继续面 → 按面试题查漏补缺；实习最适合的时间是大三
  7. 实习的四个好处：干得好直接转正、提前进入工作状态、简历上有经历、填补没有竞赛/项目经历的空白
  8. 面试策略：最想去的公司最后面，先拿不太想去的公司练手；面试考的不只是技术，还有心态
  9. C 语言大数组：静态分配受栈大小限制（多数系统 1MB–8MB），动态 malloc 只受可用内存限制；32 位进程地址空间只有 4GB；作者建议把大数组放全局
  10. 注意：文章是作者「英雄算法联盟」社群的问答与推广，含优惠券与课程链接；队长经历为作者自述，未独立核实

一、六个队长的样本，能说明什么、不能说明什么

能说明的：杭电 ACM 集训队确实产出过一批进入网易、字节和游戏公司的人，竞赛经历在游戏/后端方向有可见的敲门砖作用。不能说明的：这是六个被挑出来的「最努力最突出」的人，样本极小，也没有对照组——不能用它证明「进集训队就能进大厂」。作者自己也把队长定位成「榜样」而不是「教练」，真正带队的是教练。

二、蓝桥杯路线为什么这样排

竞赛里的 C++ 优势主要来自 STL：vector、map、priority_queue 这些容器和算法直接可用，省掉手写链表、堆、排序的时间。但作者强调「会 STL 不等于不用学数据结构」——因为比赛里真正卡人的是建模与复杂度分析，STL 只解决「怎么实现」。他给的七段路线本质是：语法 → 基础结构 → 标准库 → 基础算法 → 进阶结构与算法，顺序不能反。

三、实习的时间账：大二、大三、考研怎么排

作者的建议有明确前提：大三课少、没有其他安排时去实习最合适。大二课最多，实习往往只能做边缘工作，收益低。对准备考研的人，这条建议要反过来算——大三暑假正是备考黄金期，实习与初试时间直接冲突。判断顺序应该是：先定方向（考研/就业），再排实习；而不是用「海投」代替方向选择。
📌 原文的「先投实习再说」适合已经决定就业、需要补简历的人；如果你在备考，别被这句话带偏。把实习当成「就业方向的验证」而不是「必须完成的动作」。

四、C 语言那问的技术补充

原文说静态数组受栈大小限制、动态分配只受可用内存限制，这是对的。再补一层：全局数组放在静态存储区（.bss/.data），确实不受函数栈限制，但它仍受链接器、可执行文件大小和进程地址空间约束；「全部用全局变量」是应急手段，不是好设计。更稳的做法是 malloc 后检查返回值，或把大缓冲区做成静态池。

「REA 逆向一切」：把 Ghidra / IDA 打包成 MCP，AI Agent 开始拆系统

好机友

一句话

原文介绍一个叫「REA 逆向一切」的开源项目：它把 Ghidra、IDA、Hopper、JADX、mitmproxy、Binwalk 等逆向工具封装成 MCP 服务，接上 Codex、WorkBuddy、Claude Code 等 Agent 后，可以用自然语言驱动逆向；文章据此罗列了安卓刷 iOS/鸿蒙、Mac 跑安卓 App、iPhone 跑 Switch 游戏等案例。

深入讲解 · MCP 为什么能降低门槛，以及这些案例的可信度分层

  1. REA 是什么：把多款祖师爷级逆向工具打包成一个便捷的 MCP 服务，接到 Codex、WorkBuddy、Claude Code 等 AI Agent 工具上
  2. 怎么用：对 Agent 提一句「帮我看看这个 App 核心功能怎么实现的」，Agent 自己调工具反编译、读代码、写脚本验证；原文说人主要负责点「Yes / No」
  3. 案例·小米显示器：网友因为显示器不支持 DDC/CI 切换、按钮控制麻烦，用 AI 逆向小米显示器内置的澎湃 OS，做出快捷切换接口的软件，还加了调光、色温、分辨率、屏幕时间；作者实测能用
  4. 案例·徕卡一瞬：小米官方用徕卡 M9 实拍数十万张照片训练端侧模型；GitHub 上有项目逆向并开源了模型权重，作者把项目喂给 AI 搓了个简易 App，效果与小米 17 Ultra 的「徕卡一瞬」约八成相似
  5. 案例·安卓刷 iOS：原文称有开源项目把苹果的 XNU 内核移植出来，配合 iPhone X 的 iOS 16 系统套件，让部分安卓老机型刷入 iOS
  6. 案例·Mac 跑安卓 App：macOS 上的 Mac.APK 让安卓 App 安装后直接使用，无需模拟器或虚拟机；作者实测部分常用 App 正常、部分布局错乱
  7. 案例·iPhone 跑 Switch：项目让 Switch 游戏代码直接运行在苹果芯片上，原文称已支持马里奥、塞尔达、猎天使魔女等
  8. 其他被点名的玩法：安卓刷原生鸿蒙、安卓平板刷原生 Linux、重做电视桌面、用 adb 让 AI 自动关手机广告、逆向智能马桶做遥控程序
  9. 作者的判断：逆向的难点不在思路，而在试错和验证要花大量时间；AI 接管这些耗时活之后，门槛降到「有手就行」
  10. 注意：文中案例多为网络视频或个人演示，原文没有给项目链接与可复现步骤；「能开机」不等于「能日常使用」

一、把工具 MCP 化，降低的是「操作成本」

传统逆向的流程是：选工具 → 反编译 → 读汇编/伪代码 → 猜实现 → 写脚本验证 → 失败重来。每一步都要人切换工具、记命令、判断结果。MCP 的作用是给 Agent 一套标准化的工具接口，让它可以自己调用 Ghidra/IDA/JADX、自己读输出、自己写验证脚本。人从「操作员」变成「定目标和验收的人」——这就是原文说的「点 Yes/No」。
但要注意：降低的是操作成本，不是理解成本。Agent 不懂「这个函数为什么这样写」，也不承担「改坏了变砖」的后果。目标怎么定、结果怎么验，仍然要人来做。

二、案例的可信度要分层看

第一层，作者亲自实测：小米显示器工具、Mac.APK——有具体使用体验，可信度相对高。
第二层，有视频/截图演示：一加刷鸿蒙、小米 8 刷 iOS——能看到结果，但驱动完整性、稳定性未知。
第三层，纯转述：安卓刷原生鸿蒙、平板刷 Linux、智能马桶遥控——原文只有一句话，没有项目名和链接，无法核验。
把这三层混在一起读，很容易高估「AI 逆向已经无所不能」。

三、真正难的是驱动，不是反编译

系统移植能不能「日常用」，取决于 Wi-Fi、蓝牙、GPU、相机、基带这些驱动有没有适配。原文自己也承认，一加那台「Wi-Fi 功能未完成修复」，小米 8 的移植「很多硬件驱动还需要继续适配，暂时不能作为日常系统使用」。反编译只解决了「看懂」，驱动适配才是「能用」。

四、风险清单

① 法律/版权：移植苹果系统、任天堂游戏涉及 EULA 与版权，原文也提到任天堂的法务；
② 硬件：刷机可能变砖、失去保修，来路不明的固件还可能植入后门；
③ 数据：刷机前不备份，聊天记录和照片可能一起没；
④ 安全：把开锁、支付、账号权限交给逆向出来的程序，风险远高于省下的时间。
📌 对你更有用的落点：这套「工具 MCP 化 + Agent 编排」的思路，可以搬到自己的嵌入式调试上——把串口日志、示波器截图、编译错误交给 Agent 做初步归因，人负责定边界和验收。但底层知识（启动链、驱动模型、协议）仍是判断力的来源。

一加刷鸿蒙、小米刷 iOS：AI 加持下的「系统互相偷家」

IT之家

一句话

IT之家汇总了近期一批跨系统移植案例：一加 Ace 5 刷入 HarmonyOS 6（机型显示 Mate 80 Pro）、小米 8 / Redmi Note 12 刷入 iOS 16、Surface Duo 2 跑 iPadOS 26、HTC HD2 跑 iOS 7；共同点是移植 XNU 内核/系统组件，且大多仍处早期、驱动不全。

深入讲解 · 刷机到底刷了什么，为什么「能开机」离「能用」很远

  1. 一加 Ace 5 → HarmonyOS 6：B 站网友 10 月 25 日发布视频，刷入后机型显示华为 Mate 80 Pro，壁纸、系统动效、侧边快捷栏、应用小窗可正常使用
  2. 它的限制：刷的不是 OpenHarmony，而是华为手机预装的 HarmonyOS 6；目前不支持 HMS 驱动，Wi-Fi 功能也未完成修复
  3. 小米 8 → iOS 16.5：机型伪装为 iPhone X；最初 GPU 卡顿，修复后流畅不少；桌面显示和动画较流畅，但很多硬件驱动仍需适配，不能作为日常系统
  4. Redmi Note 12 4G → iOS 16：不是主题/启动器/模拟器，而是移植苹果开源的 XNU 内核 + iPhone X 原版用户界面；「关于本机」显示 iOS 16.7.16、iPhone X，触摸和音量键可用
  5. HTC HD2 → iOS 7：10 月 7 日公布的复古硬件移植项目，iOS 用户态组件与触摸屏已能工作；HD2 是 2009 年的「刷机之王」
  6. Surface Duo 2 → iOS / iPadOS 26：已实现双屏运行，两块屏幕可达 37 FPS（此前仅 3–10 FPS）；作者用的是屏幕有破损的「专门折腾机」，后续计划移植 iOS 27
  7. 相机也被逆向：索尼 A7C II 的定制固件解锁 FL2/FL3 胶片模式、支持导入 LUT、自定义快门声；仅支持固件 2.01，且有变砖、影响保修、副厂电池识别等问题
  8. 游戏移植：《超级马力欧兄弟：惊奇》原生移植到 Windows，RTX 3050 笔记本约 60 帧，使用重编译 C++ 代码 + NVN→Vulkan 转换层；原文提醒任天堂的版权风险
  9. 原文判断：AI 让反编译和重编译变简单，厂商壁垒「四面漏风」；但驱动、稳定性和版权仍是硬约束

一、一次「刷系统」包含四层

自下而上是：引导链（bootloader）→ 内核 → 硬件驱动 → 用户态系统与应用。网友说的「移植 XNU 内核 + iPhone X 用户界面」，实际是替换了内核和用户态，但驱动层必须针对每台机器的屏幕、触摸、Wi-Fi、GPU、电源管理逐项适配。这就是为什么演示视频里系统能亮、能滑，但 Wi-Fi 没修好、HMS 不能用、相机打不开——能开机只证明引导链和显示通了，不证明整机可用。

二、XNU 是什么，为什么这几个项目都绕不开它

XNU 是苹果 Darwin 系统的混合内核（Mach + BSD），iOS/macOS 的用户态都跑在它上面。把 XNU 和 iOS 的用户态组件移植到非苹果硬件，理论上能得到「像 iOS 的体验」；但苹果的驱动是闭源的，移植者只能自己写或借用开源驱动，这部分工作量远大于「把内核跑起来」。原文提到的 HTC HD2、小米 8、Redmi Note 12、Surface Duo 2，走的都是这条路线。

三、为什么这两三个月集中冒出来

阿波罗 11 号源码：4KB 内存如何把人类送上月球

JackCui · 小R

一句话

1969 年的阿波罗导航计算机只有 4KB 运行内存、约 72KB 只读存储，靠内存分阶段复用、8 个任务槽、手工编织的磁芯绳存储、自建虚拟机和软重启机制，跑完了一整套登月飞控程序。

深入讲解 · 4KB 怎么够用 + 虚拟机与软重启

  1. 硬件底子：AGC 重约 32 千克、功耗 55 瓦、主频约 2.048 MHz；一个字 15 位数据 + 1 位奇偶校验，没有「字节」概念，也没有浮点数，小数点位置靠程序员自己记
  2. 两套核心程序：指令舱的 Comanche055（Colossus 2A）和登月舱的 Luminary099（Luminary 1A），各约 6.5 万行（含注释）、各约 90 个文件，全部平铺在一个目录里
  3. 三层结构：底层是 EXECUTIVE（任务调度）、WAITLIST（定时任务）、中断与重启恢复；中间层是 INTERPRETER 虚拟机、数学子程序和键盘显示；上层任务文件按 P 编号命名，P63 对应登月下降
  4. 内存复用：变量分 PRM（全任务专用）和 TMP（可临时借用），并注明谁能覆盖谁；仅登月舱程序就标注了 1500 个变量
  5. 8 个任务槽：每槽 12 个字，当前任务固定 0 号槽，切换只交换 12 个字；复杂运算另领 44 字「草稿区」，全机只有 5 块。整套多任务系统约占 340 个字，只用六分之一的内存
  6. 存储是「织」出来的：72KB 用的是磁芯绳存储器，由女工在放大镜下用铜线穿过磁环编程——铜线从磁环中间穿过代表 1，从旁边绕过代表 0；穿好就改不了，因此代码必须极度严谨、常数能复用就复用
  7. 自建虚拟机：AGC 原生只有 8 条基本指令，程序员用汇编写出解释器，执行 TC INTPRET 即可进入；约 2000 字程序存储换来 28 位双精度数和三维向量运算，点乘、叉乘、单位化、矩阵乘向量都只要一条指令
  8. 软重启救命：1969-07-20 登月舱下降时警报响了 5 次，主要是 1202（任务槽用完）和一次 1201（草稿区用完）；程序靠 PHASCHNG 记录断点、BAILOUT 报警、ENEMA 重启，导航和发动机控制几乎未受影响
  9. 代码来源：不是 NASA 硬盘导出，而是 MIT 博物馆的纸质打印稿——飞行历史学者拍照、Virtual AGC 的 Ron Burkey 带志愿者逐字符录入，再用 yaYUL 汇编验证；登月舱打印稿定稿时间是 1969-07-14 16:27，离发射只剩两天
  10. 仓库：github.com/chrislgarry/Apollo-11，截至 2026 年已有约 7.5 万 Star

一、4KB 内存的三种省法

① 分阶段复用：内存位置被标上 PRM / TMP 身份，不同时运行的程序可以共用同一块 TMP；变量注释会写明「可以覆盖，但要小心，只在动力下降时使用」这类约束。
② 固定任务槽：8 个槽各 12 字，相当于极简的进程上下文，切换任务只交换两个槽的 12 个字。
③ 按需给草稿区：只有做向量、矩阵运算的任务才领 44 字草稿区，全机 5 块，用不到的任务一个字都不多给。
📌 原文的算账：多任务系统总共只占约 340 个字，用六分之一的内存就实现了调度。

二、15 位机器上的「虚拟机」

AGC 天生只认识 8 条基本指令，连乘除法都要靠前缀指令，更别说向量和矩阵。解释器只占约 2000 个字的程序存储，却能处理 28 位双精度数和 6 个字组成的三维向量。
省空间的两个细节：操作码只有 7 位（最多 128 种运算），汇编器把相邻两条指令打包进同一个 15 位字，指令空间直接省一半；虚拟机采用不需要括号的波兰表示法，操作码字存成负数、内存地址存成正数——取操作数时先看下一个字，正数就去那个地址取数，负数说明下一条已经是新指令，直接从栈里弹出上一步结果继续算。

三、1202 警报为什么不等于死机

登月最关键时刻，8 个任务槽和 5 块草稿区被同时挤满：1202 表示「没有可用的核心组」（任务槽用完），1201 表示「没有可用的草稿区」。程序没有硬撑，而是进入 BAILOUT 记下报警代码，跳到 ENEMA 清空堵塞任务，再按 PHASCHNG 留下的断点把导航、发动机控制等关键任务重新拉起来。关键任务每走到重要步骤都会记录「第几组、第几步」，这些断点存在内存里，重启不会丢。

四、比技术更值得记的两件事

① 约束逼出纪律：磁芯绳穿好就不可改，所以代码里几乎没有冗余，全篇搜不到一个 TODO 或 FIXME——在登月这件事上，没人敢把问题留到以后。
② 代码也有性格：主点火程序文件名叫 BURN_BABY_BURN--MASTER_IGNITION_ROUTINE.agc，参数表上写着 NOLI SE TANGERE（别碰我）；雷达天线注释是「PLEASE CRANK THE SILLY THING AROUND」，确认提示是「SEE IF HE'S LYING」，点火跳转注释是「OFF TO SEE THE WIZARD...」。
📌 对照你的方向：这篇讲的不是怀旧，而是资源受限系统里的工程方法——内存分区、固定上下文、断点恢复、可验证的代码来源。做嵌入式项目时，这些约束和取舍比堆功能更值得学。

一句话

DeepSeek 开源了一整套面向华为昇腾的基础设施组件，并强调"与此前面向英伟达的开源组件一一对应"——这意味着它的训练工具链第一次有了第二条硬件路线。

深入讲解 · 为什么"一一对应"是关键，软件才是真门槛

  1. 开源清单：主角是 TileLang（算子编程语言及编译支持），外加计算库 DeepGEMM、分布式通信库 DeepEP，以及 TileKernels、FlashMLA、DeepSelect（向量计算与访存、稀疏注意力、Top-K 选择等）
  2. TileLang 的分量：相较 CUDA 能简化代码逻辑、提高开发效率；先在英伟达平台验证，如今已承载 V4 系列模型训练中大部分算子的实现——是 DeepSeek 开发高性能算子的核心工具
  3. 昇腾版的实现方式：封装底层 Ascend C 指令。DeepSeek 称"目前训练中使用的每一个 TileLang 算子，在昇腾上都有对应的高性能实现"

算子是什么，为什么它决定一切

大模型研究里的新想法，必须通过算子翻译成芯片能执行的计算。算子开发越复杂，研究者验证新结构、优化训练效率所需的时间就越长。所以"用什么语言写算子"直接决定了一个硬件平台对模型团队的友好度——这也是为什么 TileLang 比那几个库更值得关注。

如果只是"能在昇腾上跑 DeepSeek 模型"，那叫推理适配，生态里早就做了很多轮。而这次是把手写算子、通信库、矩阵库这一整套研发工具搬过去，且声称与英伟达版一一对应。原文举的例子很实在：TileKernels 支持同一套 Python 接口在英伟达 GPU 与华为 NPU 上运行，底层实现按硬件自动选择。

ESP32 滚纸写字机：把 Y 轴换成"滚纸"，能写 5 米长

立创开源硬件平台

一句话

常见写字机是方方正正的 XY 平台——10cm 的纸就要 10cm 的机器；这个项目把 Y 轴改成滚纸轴，用三轴实现 210mm × 5000mm 的书写范围，DIY 成本约 350 元（市售同类 600–1000+）。

深入讲解 · 三轴联动原理与复刻要点

  1. 三轴分工：X 轴让笔左右移动 · Y 轴让纸前后滚动 · Z 轴用舵机负责抬笔落笔。理论上只要纸够长、软件行程继续增大，5 米也不是物理极限
  2. 主控：立创·ESP32S3R8N8 开发板；电路用嘉立创 EDA 设计，板子尺寸可免费打样
  3. 驱动：两路 TMC2209-LA-T 分别驱动两台 42 步进电机——支持最高 256 微步，带 StealthChop 静音驱动，运动更细腻平滑、不易丢步打滑，且有过温短路保护
  4. 电源与外围：TPS54202DDCR BUCK 降压、MicroSD 卡座、滑动开关 SS12D06G5、拨码开关 DSWB02LHGET、XH-4AW 线对板针座
  5. 软件几乎零开发：依托 ESP32 生态，可直接跑 FluidNC 运动控制固件，配合炽写3、GRBL Studio、奎享等软件写字绘图
  6. 作者自己说的短板：没有产品级精度，还缺限位开关——但已经能实际完成写字和绘图，且开源了足够复刻的资料
  7. 开源地址：oshwhub.com/ymengo/project_mraukvnb

为什么"滚纸"是个聪明的设计

传统 XY 平台里，机器的占地面积必须大于纸张面积——想画 1 米长的图，就得有 1 米长的机器。把 Y 轴从"移动笔"改成"送纸"，等于把空间需求转成了卷材需求：机器本身很细长，纸可以一直往后送。原文还顺手点出这是笔式绘图仪（pen plotter）的原理，能画长线稿。

三轴是怎么联动的：STEP/DIR 信号链

工作流是：运动文件/指令 → ESP32-S3 解析 → 计算各轴运动 → 输出 STEP/DIR 信号 → 步进驱动器 → 步进电机运动。
大白话讲：要让机构向右移动，ESP32 就让对应电机驱动器收到一定数量的 STEP 脉冲（脉冲数 = 走的步数）；要反向运动，就改变 DIR 电平。三路电机组合起来，就能完成 X/Y/Z 三轴联动。这也是所有 CNC / 3D 打印机 / 写字机通用的控制抽象——理解了这一层，换任何运动控制项目都能上手。
