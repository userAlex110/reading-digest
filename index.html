AI 工具EARS · 小耳 · 09-19

不缺 Token 的 Tibo 怎么工作：把「人」从流程里拿出来

一句话：OpenAI Codex 负责人 Tibo Sottiaux 的工作法核心不是"打字更快"，而是把工作移动化、异步化、自动化——人只在两头出现：早上口述意图，关键节点审批边界。

  • 晨间语音口述：早上喝咖啡时根本不开电脑，拿手机用语音向 AI 汇报今天目标，AI 自己读日历、邮件、Slack 并安排下去
  • 隔夜异步批处理：夜里遇到复杂架构问题、白天没空深挖的思考、长程重构，不熬夜，直接丢给云端静默跑一整夜，早上看报告
  • "30 分钟"全局情报：想了解社区反馈 / 生产日志 / 哪些低频功能该废弃，不开会、不要 PPT，直接发个任务，半小时拿到结构化排查报告
  • 单日原型雕刻与释放：想法不留在概念阶段，一天内用语音＋Agent 雕出可运行原型，推给团队批判，然后立刻"释放"认知负荷做下一件
  • 像"训宝可梦"一样攒 Skill 库：定时总结 Slack 动态、自动解 Git 冲突修 Build、甚至让 AI 每天随机挑一个代码文件去找潜伏 Bug
  • 他自己说的瓶颈："模型已经可以在云端一下子干几百个活，但你还是习惯开一个窗口交代任务、等反馈、再说下一个——一天下来，我自己才是最大的天花板"
深入讲解 · 三个范式转移 + Token 有限时的实操策略

转移一：从"盯着过程"到"定义盒子与不变量"

过去人累，是因为精力都花在盒子内部的具体实现上。新范式里，人的真正价值是定义边界——和 AI 明确输入输出契约、资源限制、安全边界、系统不变量（Invariants）。盒子内部是 1 个 Agent 写还是 100 个并发生成，人根本不用关心。

转移二：从"审查正确性"到"审查意图"

当生成速度极高，检查语法、拼写、低级逻辑错误会耗尽人的注意力。OpenAI 内部把代码正确性与安全校验彻底交给自动化 AI Review 模型，人的审查全面转向意图审查——"你到底想解决什么问题？这件事值不值得做？"

转移三：注意力友好的交互

同时盯 10–15 个 Agent 窗口、频繁切换上下文，脑子很快就崩。正确姿势是保持"心流实时雕刻"：只保留 2–3 个核心任务，像和专家对话一样实时调整意图（mid-term steering），重度任务则完全静默托管给云端。

💡 原文的启发总结：提升生产力的突破口不是训练自己打字更快，而是训练自己表达意图更精准。建立属于自己的 Skill 自动化库，把日常繁琐、重复的搜集和校验交给后台 Agent，你只负责口述意图和关键审批。
📌 对照你自己：你正在搭的「凌晨 1 点自动归档微信收藏」就是这套思路的最小实践——把"攒了要读"变成后台静默完成，早上起来直接看成品。Tibo 的"隔夜异步批处理"说的正是这件事。

AI 工具腾讯科技 · 09-30

DeepSeek 加速向华为靠拢：把自家研发工具搬到昇腾上

一句话：DeepSeek 开源了一整套面向华为昇腾的基础设施组件，并强调"与此前面向英伟达的开源组件一一对应"——这意味着它的训练工具链第一次有了第二条硬件路线。

  • 开源清单：主角是 TileLang（算子编程语言及编译支持），外加计算库 DeepGEMM、分布式通信库 DeepEP，以及 TileKernels、FlashMLA、DeepSelect（向量计算与访存、稀疏注意力、Top-K 选择等）
  • TileLang 的分量：相较 CUDA 能简化代码逻辑、提高开发效率；先在英伟达平台验证，如今已承载 V4 系列模型训练中大部分算子的实现——是 DeepSeek 开发高性能算子的核心工具
  • 昇腾版的实现方式：封装底层 Ascend C 指令。DeepSeek 称"目前训练中使用的每一个 TileLang 算子，在昇腾上都有对应的高性能实现"
  • 硬件协同：双方共同推进基于昇腾 950 的 128 卡超节点方案，对计算与通信做深度优化；多项关键测试用例性能已接近硬件上限（属特定测试条件下的结果）
  • 时间线：2025.8 V3.1 的 UE8M0 FP8 设计"面向即将发布的下一代国产芯片" → 2025.9.29 V3.2-Exp 发布 + TileLang-Ascend 开源 → 2026.4.24 V4 预览版，昇腾适配已延伸至推理和训练侧
  • 背景数字：梁文锋在投资者会议上称 DeepSeek 超过 70% 算力用于模型训练，留给推理的不足 30%；500 亿元第二轮融资接近结束，已聘中信证券筹备科创板 IPO
深入讲解 · 为什么"一一对应"是关键，软件才是真门槛

算子是什么，为什么它决定一切

大模型研究里的新想法，必须通过算子翻译成芯片能执行的计算。算子开发越复杂，研究者验证新结构、优化训练效率所需的时间就越长。所以"用什么语言写算子"直接决定了一个硬件平台对模型团队的友好度——这也是为什么 TileLang 比那几个库更值得关注。

"一一对应"的含金量在哪

如果只是"能在昇腾上跑 DeepSeek 模型"，那叫推理适配，生态里早就做了很多轮。而这次是把手写算子、通信库、矩阵库这一整套研发工具搬过去，且声称与英伟达版一一对应。原文举的例子很实在：TileKernels 支持同一套 Python 接口在英伟达 GPU 与华为 NPU 上运行，底层实现按硬件自动选择。
代价是——接口能复用，性能仍需针对硬件打磨。所以才有"双方围绕 128 卡超节点共同优化计算与通信"这一段，以及公告里对华为"毫无保留的大力支持"的致谢。

真正的瓶颈不是芯片，是软件

原文的判断：资金可以支持研发和基础设施投入，但新增硬件能否转化为有效算力，取决于软件适配与运行效率。对 DeepSeek 来说，昇腾上的工具与组件越完善，未来换算力平台时要重新投入的工程成本就越低；对华为来说，与模型团队共同优化，能让芯片软件更快跟上模型结构的变化。
⚠️ 冷静看：DeepEP 昇腾版仍列有开发中的功能，此次公告也未披露 V4 已在昇腾上完成全流程大规模训练。从"组件开源"到"稳定承担大规模生产任务"，中间还有活要干。另外文中提到 DeepSeek 希望这套东西"为更多 AI 芯片建立高可用软件生态起到示范作用"——如果别的团队能复用，更多国产芯片承接前沿模型的门槛也会降低。

和你有什么关系

你在做嵌入式、也在准备考研。这条新闻的价值不在"谁赢"，而在它示范了一件事：决定技术路线的往往不是峰值算力，而是软件生态的迁移成本。同一个道理在嵌入式和操作系统选型上反复出现——这也是 TOPS 那篇文章（上一期收录）说的是同一件事。

嵌入式立创开源硬件平台 · 09-11

ESP32 滚纸写字机：把 Y 轴换成"滚纸"，能写 5 米长

一句话：常见写字机是方方正正的 XY 平台——10cm 的纸就要 10cm 的机器；这个项目把 Y 轴改成滚纸轴，用三轴实现 210mm × 5000mm 的书写范围，DIY 成本约 350 元（市售同类 600–1000+）。

  • 三轴分工：X 轴让笔左右移动 · Y 轴让纸前后滚动 · Z 轴用舵机负责抬笔落笔。理论上只要纸够长、软件行程继续增大，5 米也不是物理极限
  • 主控：立创·ESP32S3R8N8 开发板；电路用嘉立创 EDA 设计，板子尺寸可免费打样
  • 驱动：两路 TMC2209-LA-T 分别驱动两台 42 步进电机——支持最高 256 微步，带 StealthChop 静音驱动，运动更细腻平滑、不易丢步打滑，且有过温短路保护
  • 电源与外围：TPS54202DDCR BUCK 降压、MicroSD 卡座、滑动开关 SS12D06G5、拨码开关 DSWB02LHGET、XH-4AW 线对板针座
  • 软件几乎零开发：依托 ESP32 生态，可直接跑 FluidNC 运动控制固件，配合炽写3、GRBL Studio、奎享等软件写字绘图
  • 作者自己说的短板：没有产品级精度，还缺限位开关——但已经能实际完成写字和绘图，且开源了足够复刻的资料
  • 开源地址：oshwhub.com/ymengo/project_mraukvnb
深入讲解 · 三轴联动原理与复刻要点

为什么"滚纸"是个聪明的设计

传统 XY 平台里，机器的占地面积必须大于纸张面积——想画 1 米长的图，就得有 1 米长的机器。把 Y 轴从"移动笔"改成"送纸"，等于把空间需求转成了卷材需求：机器本身很细长，纸可以一直往后送。原文还顺手点出这是笔式绘图仪（pen plotter）的原理，能画长线稿。

三轴是怎么联动的：STEP/DIR 信号链

工作流是：运动文件/指令 → ESP32-S3 解析 → 计算各轴运动 → 输出 STEP/DIR 信号 → 步进驱动器 → 步进电机运动。
大白话讲：要让机构向右移动，ESP32 就让对应电机驱动器收到一定数量的 STEP 脉冲（脉冲数 = 走的步数）；要反向运动，就改变 DIR 电平。三路电机组合起来，就能完成 X/Y/Z 三轴联动。这也是所有 CNC / 3D 打印机 / 写字机通用的控制抽象——理解了这一层，换任何运动控制项目都能上手。

选型上的两个好处

选择带来的好处
主控ESP32-S3 ＋ 现成固件不用自己写运动控制软件，直接跑 FluidNC，配现成上位机；复刻时调试难度大幅降低
驱动TMC2209 ×2256 微步 ＋ 静音驱动 → 运动细腻平滑、不易丢步，写字不"顿挫"；带过温/短路保护
📌 作为练手项目的价值：它把"嵌入式控制 + 机械传动 + 开源固件生态"三件事串在一个 350 元的盒子里，而且有完整的原理图 / PCB / BOM。如果以后要做一个自己的硬件作品放进履历，这类"能跑起来、能看见效果、成本可控"的项目比纯软件 demo 更有说服力。
💡 原作者的降级提示：这个方案没有产品级精度，也还没加限位开关（意味着回零和防撞需要自己补）。复刻时这两点是第一个要改进的地方。
